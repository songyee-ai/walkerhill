## 1. 제품의 목표와 범위

공개 근거를 갖춘 페르소나가 워커힐을 방문하는 과정에서 어떤 서비스를 이용·구매할지 조건별로 계산하고, 개인화 프로모션 후보를 만들어 미실시 대비 전체 여정의 매출 변화를 비교한다.

연결 흐름은 `서비스·근거 목록 → 페르소나와 방문 조건 → 방문·소비 시뮬레이션 → 프로모션 후보 생성 → 동일 조건 비교 → 서비스별 제안서`다.

서울 워커힐 단지의 그랜드·비스타·더글라스를 우선 범위로 제안한다. 객실, 다이닝, 인룸다이닝, 휴식·문화 공간, 레저·웰니스, 가족·반려동물, 웨딩·연회·기업행사, 예약·이동 편의, 멤버십·쇼핑을 목록화한다. 공항 라운지·다락휴·환승호텔 등은 별도 범위로 확장할 수 있게 한다. 운영 주체가 다른 시설도 구별한다.

‘전체 적용’은 기준일의 서비스 목록 모든 항목에 대해 각 페르소나의 적합성을 평가했다는 뜻이다. 모든 서비스에 구매를 발생시키거나 모든 고객에게 모든 서비스를 추천하지 않는다. 추천·조건부 추천·부적합·정보 부족과 이유, 목록의 누락·미확인 상태를 보여준다.

## 2. 페르소나와 고객 상태

공식 푸드·힐링·액티비티 유형은 참고 태그로 보존하되, 가족·커플·비즈니스 같은 방문 목적과 일대일로 고정하지 않는다. 프로젝트의 취향 점수와 선택 규칙은 별도 설계 가정이다.

| 구분 | 주요 항목 |
|---|---|
| 선호와 요구 | 미식·휴식·활동 선호, 조용함, 이동 선호, 식사 취향, 필요한 접근성 조건 |
| 이번 방문 | 방문 목적, 동행 구성, 날짜, 도착·출발 시간, 투숙 호텔, 예약·패키지 |
| 예산 | 1인 또는 동행 전체 기준, 이미 결제한 금액, 추가 소비 예산 |
| 변화하는 상태 | 현재 시간·장소, 남은 예산, 보유 혜택·잔여 크레딧, 예약, 이전 소비, 다음 일정 |
| 행동 가정 | 선택 민감도, 식사 이후 수요 변화, 대기 허용 정도, 프로모션 반응의 가정 범위 |
| 근거 수준 | 공식 사실, 후기에서 관찰한 요구, 설계 가설, 미확인 사항 |

성별·연령만으로 구매 성향을 결정하지 않는다. 연령은 실제 이용 자격 등의 조건으로 사용하고, 동기·취향은 입력·근거와 구분해 관리한다. 행동을 추정하는 피로도·허기 등의 상태는 관측값처럼 표시하지 않는다.

## 3. 장소마다 소비를 예측하는 방식

장소 방문, 서비스 이용, 결제를 구분한다. 각 방문 단계에는 `유료 구매 / 포함 혜택 사용 / 무료 이용·둘러보기 / 미구매 / 다른 장소로 이동`을 허용한다.

1. 운영 기간·시간, 투숙 자격, 연령, 동행 조건, 예약, 이동·이용 시간, 남은 예산을 확인한다.
2. 가능한 서비스와 ‘아무것도 구매하지 않음’을 후보로 만든다.
3. 고객 선호, 직전 소비, 다음 일정, 가격과 프로모션에 따라 후보를 비교한다.
4. 선택 후 예산·시간·혜택·시설 잔여 용량을 갱신하고 다음 단계로 이동한다.
5. 여러 고객이 함께 실행되면 같은 시간대의 좌석·재고·프로그램 정원을 공동으로 사용한다. 만석이면 대기·대체·포기를 반영한다.

방문 자체도 예측하는 모드와 사용자가 경로를 지정한 모드를 구분한다. 경로 지정 모드에서는 방문을 조건으로 소비만 계산한다. 여러 구매확률을 독립적으로 곱해 예산 초과·식사 중복·동시 이용을 만드는 방식을 피한다.

공개 자료만 사용하는 초기 버전의 구매확률·할인 반응은 조정 가능한 가정이다. 예를 들어 ‘구매확률 40%’에는 추정 근거와 가정 범위를 붙인다. 정보가 부족하면 단일 확률을 꾸며내지 않고 계산 보류 또는 가정 입력 대상으로 남긴다.

개인 화면에는 가능한 경로와 조건부 선택 가능성, 대표 실행 결과를 보여준다. 가상 고객 집단의 반복 실행에서는 서비스별 방문 수·구매량·결제액 범위를 보여준다. 반복 실행의 변동 범위는 실제 고객 예측의 정확도나 통계적 신뢰구간을 뜻하지 않는다.

## 4. 소비 원장과 매출 계산

한 행에 서비스 ID, 방문 단계, 수량·판매 단위, 정가, 할인, 크레딧 사용, 추가 결제액, 혜택 사용량, 선택 이유를 저장한다. 결제 날짜와 이용 날짜를 구별한다.

- `1인 / 1세트 / 1객실박 / 1회`를 구별하고 동행 인원에 맞춰 수량을 계산한다.
- 이미 결제한 객실·패키지는 한 번만 기록한다. 포함 조식·입장권·식음 크레딧 사용을 새 매출로 중복 합산하지 않는다.
- 추가 소비 예산에 선결제 금액을 다시 차감하지 않는다. 총 여행 예산과 추가 소비 예산을 구별한다.
- 객실·식음 부문 간 패키지 내부 배분이 필요하면 총매출과 별도로 표시해 합계가 늘어나지 않게 한다.
- 고객 추가 결제액, 모델 매출, 가정 공헌이익을 다른 지표로 표시한다. 세금·수수료·할인·환불 처리 기준을 명시한다.
- 공식 표시 가격, 시작가, 실제 거래가격, 제휴 정산가격을 같은 값으로 취급하지 않는다.
- 원가가 없으면 이익은 ‘산정 불가’로 표시한다. 임의 원가를 사용한 경우에는 원가 가정이 붙은 결과로만 제시한다.

기대 매출은 조건을 지키며 완료한 여러 소비 경로의 결제 합계로 계산한다. 고객·상품·업장·전체의 합계는 같은 소비 원장에서 산출한다.

## 5. 프로모션 후보를 만드는 기능

후보 유형은 다른 서비스와의 연계 구매, 상위 구성 선택, 묶음 상품, 비혼잡 시간대 혜택, 최소 구매 조건 혜택, 체류 상황에 맞는 추가 서비스, 재방문 제안이다. 할인 없는 안내·동선 개선도 비교 후보로 포함한다.

| 제안 카드 항목 | 내용 |
|---|---|
| 대상 | 어떤 페르소나와 방문 조건에 적용하는가 |
| 제안 시점 | 예약 전, 도착 전, 체크인, 식사 전후, 퇴실 등 |
| 해소할 문제 | 미구매·서비스 이탈·정보 부족·시간 제약의 원인 |
| 제공 내용 | 대상 서비스, 할인·증정·묶음·안내 방식 |
| 적용 조건 | 기간·시간대·최소 구매·사용 횟수·정원·중복 혜택 여부 |
| 상태 | 현재 운영 중인 혜택, 신규 제안, 운영 확인 필요 |
| 예상 효과 | 추가 구매, 업장별 변화, 전체 여정의 증분 매출, 비용 정보가 있을 때의 공헌이익 |
| 불확실성 | 구매 반응·원가·이용량 가정, 결과가 바뀌는 조건 |
| 평가 계획 | 대상 집단, 비교 조건, 측정 기간, 측정할 결과 |

모든 고객·서비스에 프로모션을 강제하지 않는다. 이미 혜택이 충분하거나 공급이 부족하거나 증분 효과가 불리한 경우 ‘제안하지 않음’을 결과로 낼 수 있어야 한다.

LLM은 공개 근거 정리, 선택 이유 설명, 후보·문안 생성을 맡는다. 가격·자격·예약·재고·예산·중복 혜택과 계산은 규칙으로 검사한다. LLM이 생성한 호감 표현을 구매확률 또는 매출 증가의 검증 근거로 사용하지 않는다.

## 6. 프로모션 전후 비교

미실시와 실시를 동일한 고객 집단, 기간, 날씨, 초기 예산·예약·혜택, 공급 조건에서 비교한다. 선택 결과와 방문 경로는 프로모션 때문에 달라질 수 있다. 확률 계산에서는 비교 실행에 대응되는 난수 조건을 사용하고 여러 차례 반복해 무작위 차이를 확인한다.

`증분 매출 = 프로모션 실시 시 전체 여정 매출 − 미실시 시 전체 여정 매출`

전체 여정을 비교해 원래 구매할 고객에게 지급한 할인, 다른 업장 구매의 감소, 무료·포함 혜택, 공급 한도로 놓친 판매를 반영한다. 이미 비교 원장에 반영된 손실을 다시 차감하지 않는다. 재방문·예약 시기 이동을 다루려면 두 실행의 평가 기간을 충분히 동일하게 잡고 기간 밖 효과는 미산정으로 표시한다.

‘구매율이 반드시 높아진다’는 가정을 강제하지 않는다. 반응 없음과 부정적 반응도 포함한다. 관측 자료가 없는 반응 계수는 여러 값으로 바꿔 결과와 손익분기 조건을 비교한다. 유리한 가정에서만 효과가 나는 후보와 다양한 가정에서 유지되는 후보를 구별한다.

다음은 실제 워커힐 가격·성과가 아닌 설명용 가상 예제다. 계산 단순화를 위해 금액은 동일한 세금 제외 기준이고 기타 비용은 제외했다.

| 항목 | 미실시 | 10% 할인 실시 |
|---|---:|---:|
| 적격 고객 | 100명 | 100명 |
| 구매율 가정 | 20% | 25% |
| 구매 수량 | 20개 | 25개 |
| 할인 반영 단가 | 50,000원 | 45,000원 |
| 매출 | 1,000,000원 | 1,125,000원 |
| 단위 변동원가 가정 | 30,000원 | 30,000원 |
| 공헌이익 | 400,000원 | 375,000원 |

매출은 125,000원 증가하지만 공헌이익은 25,000원 감소한다. 구매율 25%도 가정이므로 실제 성과로 표시하지 않는다. 같은 가정에서 매출 유지에는 구매율 약 22.23% 이상, 공헌이익 유지에는 약 26.67% 이상이 필요하며, 정수 고객 수로는 각각 23명·27명 이상이다.

## 7. 공개 근거를 활용한 설계 예시

아래의 새로운 조합·안내 방식은 프로젝트 제안이며 호텔의 현재 개인화 기능으로 단정하지 않는다. 현재 제공 중인 혜택 자체를 신규 발명으로 표시하지 않는다.

| 공개 사실 | 소비 예측에 반영 | 프로젝트 제안 후보 |
|---|---|---|
| OH, MY PET 패키지에 룸서비스 크레딧 10만원이 포함되고, 레스토랑·바에 반려동물 동반이 제한됨 | 크레딧 사용과 추가 결제 분리, 동행 조건에 맞지 않는 선택 제외 | 객실 식사 안내 시 보유 크레딧과 초과 지출을 함께 보여주고 필요한 추가 메뉴만 비교 |
| 더뷔페 관련 공식 발표에 와인 컨시어지 구매 와인은 최대 2병까지 콜키지 면제 안내가 있음 | 기존 혜택을 기준 시나리오에 포함, 와인 구매와 식사를 연결 | 와인에 관심을 표현한 적격 고객에게 해당 혜택을 안내하는 시점·방식의 효과 비교 |
| 워커힐 AI 가이드는 이미 유형 분석과 추천 여정, 식당 예약을 제공한다고 발표함 | 기존 추천을 비교 대상으로 정의할 때 실제 확인 가능한 범위만 사용 | 서비스 선택·미구매 이유, 전체 여정 결제, 프로모션 비교까지 연결 |

## 8. 최소 화면과 데이터 계약

화면은 네 부분으로 연결한다.

1. 방문 조건과 페르소나: 동행, 날짜, 투숙·패키지, 예산과 선호, 근거·가정 확인.
2. 여정·소비 타임라인: 장소별 선택 후보, 구매/미구매, 금액·혜택, 남은 시간·예산.
3. 프로모션 실험: 후보 카드, 반응 가정 범위, 동일 조건의 미실시/실시 비교.
4. 서비스별 결과: 방문·이용·구매, 미구매 이유, 매출 변화, 공급 제한, 전체 서비스 평가 상태.

필요한 데이터 묶음은 `Service`, `Evidence`, `Persona`, `VisitContext`, `Entitlement`, `JourneyEvent`, `Consumption`, `Promotion`, `SimulationRun`이다. 설명용 이름이며 특정 DB나 구현 스택을 요구하지 않는다. 실행 기록에는 입력, 출처·규칙·가정 버전, 난수 조건, 비교 결과를 저장한다.

서비스·페르소나·프로모션 규칙을 데이터로 추가할 수 있게 한다. 시연용 대표 사례의 수와 엔진이 지원하는 서비스 범위를 구분한다. 상호작용·비용·반응을 확인하지 못한 조합은 정보 부족 상태를 유지한다.

## 9. 구현 순서와 완료 조건

먼저 페르소나 1개와 방문 경로 1개에서 구매·미구매·포함 혜택을 끝까지 계산한다. 그 소비 원장을 기반으로 프로모션 1개를 미실시와 비교한다. 이후 서비스 목록과 다른 페르소나를 추가하고 공동 정원과 집단 반복 실행으로 확장한다. 대표 사례는 발표용 예제이고, 모델의 고정된 전체 분류가 아니다.

아래는 향후 구현의 완료 조건이며 현재 모두 미검증이다.

- [ ] 서비스 목록의 범위·기준일·누락·정보 부족 상태가 표시된다.
- [ ] 같은 가족 방문이라도 선호·예산·자녀 연령·도착 시간에 따라 후보와 선택이 달라진다.
- [ ] 방문해도 구매하지 않을 수 있고 미구매 이유가 남는다.
- [ ] 포함 혜택과 선결제·크레딧이 추가 매출로 중복 계산되지 않는다.
- [ ] 예산, 이동·이용 시간, 운영 시간, 자격, 예약, 공동 정원 조건을 지킨다.
- [ ] 개인 원장·상품·업장·전체 합계가 일치한다.
- [ ] 고정된 입력·규칙·난수 조건으로 결과를 재현할 수 있다.
- [ ] 프로모션 전후에 같은 초기 집단·공급 조건을 사용하고, 경로 변화도 비교한다.
- [ ] 기존 구매 할인과 다른 업장 소비 감소가 전체 결과에 반영된다.
- [ ] 반응 없음·부정적 반응·공급 부족에서는 효과가 없거나 음수로 나올 수 있다.
- [ ] 원가 미확인 시 이익을 산정 불가로 표시한다.
- [ ] 서비스·제안의 공식 근거, 설계 가정, 미확인 사항을 구분한다.
- [ ] 가상 반복 실행만으로 실제 고객의 구매확률·만족도·매출 증가가 검증됐다고 표시하지 않는다.

실제 자료를 사용할 수 있게 되면 별도 보호된 환경에서 선택·구매확률을 보정하고, 시점이 분리된 관측 자료로 정확도를 평가한다. 프로모션의 실제 증분 효과는 적절한 대조군을 둔 실험 등으로 검증한다. 공개 저장소에는 공개 근거와 가상 예시만 둔다.
